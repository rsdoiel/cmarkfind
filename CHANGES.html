Change log

Unreleased

  • fill -site-url ADDRESS (folders): store every page under the address the site is published at (scheme, host and path prefix), whatever its outline lists. Without it, pages a relative outline link resolves to are stored under http://site.local/ and fill warns on standard error.
  • verbs [-json] lists the verbs with a line each; -json adds each verb’s options (and indexer’s subverbs), read from the verbs themselves. New help topics verbs and completion.
  • completion bash|powershell writes a tab-completion script for the verbs, indexer’s subverbs, each verb’s options, the help topics and file names. -install writes it where the shell loads it ($XDG_DATA_HOME/bash-completion/completions/cmarkfind and a line in ~/.bashrc, or beside the PowerShell profile) and never overwrites a file it did not write; -uninstall removes only what it wrote; -check says whether it is set up. The verb list is one table that dispatch, verbs and completion share.
  • New exit status 74 (a read or write failed part way), used by completion -install; completion -uninstall and -check exit 1 when there is nothing to remove or a problem.
  • A word on more than a million pages stops the index build (exit 73, naming the word and its page count) instead of writing an index no search could read; the index already in place is kept.
  • A search no longer reads the text of every page it finds: the address of a page is in the index’s document table, so ranking costs the matches’ postings and not their page text. A word on 20,000 pages searched in 1.7 s and now in 0.11 s; a common character in a 3 million character corpus 0.29 s, now 0.14 s. An index written before is read the old way until the next fill rebuilds it.
  • Pin and tag: pin and unpin mark a page by its address so a pinned match is listed first; tag and untag give a page your own tags (letters, digits, -, _; folded to lower case; not part of the searched text). pin -list and tag -list [ADDRESS] show them. Pins and tags are kept by forget and by a refill.
  • search -tag TAG (repeatable, a page must carry every tag) and search -pinned; with either, the query may be left out and the pages that qualify are listed by title. JSON hits gain pinned and tags; stats gains pinned, tags and tag_pages.
  • Schema version 4 (two new tables); a version 3 file is upgraded in place. A cmarkbrowser built for schema 3 exits 65 on a version 4 file until it is released against this version: release cmarkfind first, then cmarkbrowser.
  • Four new help topics: pin, unpin, tag, untag.
  • Search reads the partitioned index (Lucene-style query language, BM25 with title 4, description 2, body 1) and not SQLite FTS5. fill, forget and exclude rebuild the index beside the corpus file (or in CMARKFIND_INDEX) when they changed pages; a search that finds it missing, or not the one this corpus built, builds it first (about 3 s for 340 pages, 6 s for 1,800). indexer build and search -index DIR stay.
  • Schema version 5: the FTS5 table and its triggers are dropped on the first open (run VACUUM to give the space back). An older cmarkbrowser exits 65 on a version 5 file; move it to this cmarkfind first.
  • Query differences from FTS5: -word and title:word are in; NEAR(), ^word, column sets {a b}: and a prefix on a phrase are not (read as words). Snippets are the 14 words with the most matches, not FTS5’s. Pins, tags and tier ties work as before.
  • search prints hits as a Markdown list of working links (- [Title](address), then tier, pins and tags, then the snippet with matches in bold). The link ends in #heading when the match is under a heading below the page’s title (JSON hits gain anchor). Titles and addresses are escaped, and control characters are dropped. -json is unchanged.
  • A rebuild no longer breaks a search running at the same time: files are written to a temporary name and renamed, manifest.json last, and files the new manifest drops, and temporary files a dead build left, are pruned only when ten minutes old. Two builds at once (a fill and a search) are safe.
  • An index folder has one owner: the first corpus to build into it writes .cmarkfind-owner, and a second corpus pointed at the same CMARKFIND_INDEX is refused with exit 78 (config) instead of rebuilding over the first on every search. A folder with no owner file is adopted by the first corpus that builds it.
  • A query over the size limit exits 2; an index that cannot be written exits 73.
  • Search ignores case and spelling forms the way people expect across languages: words are normalized to Unicode NFKC and case folded, so precomposed and decomposed accents, ligatures, full-width letters and the German sharp s match their plain forms (café and cafe with a combining accent, ﬁne and fine, Straße and STRASSE). Accents are not removed (naïve and naive stay different). An index built by an earlier cmarkfind is rebuilt on first use.
  • A word on very many pages no longer stops the index from building. A word whose entry passes 2 MiB (a language’s “the”, “de” or “und”, or a date that every page repeats) is stored without positions: search still finds the pages and fields, a phrase through it is checked against the text of each hit, so results stay exact, and the word is marked in snippets from the page’s text. indexer build prints these words with counts, indexer list and stats list them, and a fill, forget or exclude warns on standard error when the set changes. Words of more than 128 bytes are not indexed. A file too big even so names the word and exits 73, leaving the old index in place.
  • Chinese and Japanese text is searchable: a Han, Hiragana, Katakana or Bopomofo character (and ー) is a word of its own, so 猫 finds a page of 吾輩は猫である and 名前はまだ is the phrase of its characters, a substring search with no dictionary. A change of script ends a word (iPhone手机 is iPhone, 手, 机); half-width katakana and decomposed kana match the normal forms. Snippets show Chinese and Japanese without spaces between characters and a longer window. Korean words are indexed as written, and a Korean query word of two or more syllables is read as a prefix, so 한국어 finds 한국어를 (a quoted word is exact); Thai, Lao, Khmer and Burmese are not segmented. A page of about two million CJK characters or more is too big for one index file: it is left out of the index with a warning that names it (stats lists it under “not indexed”), and the corpus stays searchable. The index words changed again, so an index is rebuilt once on first use.
  • A phrase of very common words (four of the commonest Chinese characters in a row, or of the) is about ten times faster on a long page: the places of the word with the fewest are tried and each is checked by lookup, not by scanning the page.
  • An index file with extra trailing elements in a record (a later writer’s addition) is read, as the format promises; before, only postings tolerated them.
  • Index sets: every site the corpus holds pages for (a table of contents on the web, or a folder) is a set with an index of its own, under index/sets/ beside the corpus (or CMARKFIND_INDEX). search reads every set and merges them by reciprocal rank fusion; search-set SET QUERY reads one. set list, set show SET, set ignore SET, set unignore SET and set fields SET manage them: an ignored set is left out of search and still reached by search-set. A set is named by its address with or without the scheme (rsdoiel.github.io) or by its folder. fill makes a set and forget removes it with its index.
  • There is no longer one index for the whole corpus: a fill or an exclusion rebuilds only the sets whose pages changed, and indexer build [SET], indexer validate [SET] and indexer list [SET] take a set and not a folder. search -index DIR and indexer build DIR are gone (neither was released). The first build removes the old corpus-wide index files. A set’s folder is a complete index that can be published as it is.
  • Schema version 6 (the sets and collections tables). An older cmarkbrowser exits 65 on a version 6 file; move it to this cmarkfind first. New help topics set and search-set.
  • Collections: fill -name NAME FOLDER reads a folder of Markdown files with no outline (.md and .markdown, any depth; dot files and folders, symbolic links and files over 8 MiB are left out) as the collection NAME, stored under collection://NAME/relative/path.md. A collection is an index set: search-set NAME, set ignore NAME, exclude collection://NAME/drafts/, forget NAME. The folder is remembered; another folder under the same name is refused until forget. A program opens a page with corpus.CollectionFile, which refuses .., encoded .. and symbolic links out of the folder. set show names a collection’s folder.
  • A set whose index is kept in a word rule this program does not read (an index fetched from elsewhere, from a later version) is left out of search with one warning, never mixed with the others; search-set on it exits 65. A set built here is simply rebuilt.- Front matter is kept: each page’s YAML header is stored with it (schema version 7, pages.meta) and abstract stands for description when a page has none. A page stored before this is read again by the next fill (a web page is fetched once more, without If-None-Match).
  • set fields SET shows how a set reads front matter, a line for each field with its roles (facet, fielded, date, text); set fields SET author=facet,fielded tags=facet keywords=none sets them and -reset returns the set to the default. A change makes the next build replace the set’s index. A date field that holds something that is not a date is warned about, once for the page and field, and the page is left without it.

v0.0.1, 2026-11-26

First release: a personal search engine for the Markdown web.

  • The corpus: Markdown pages in one SQLite3 file, searched with FTS5 and ranked by bm25, ties broken by tier. Pure Go (github.com/glebarez/go-sqlite), no cgo. Schema version 3; older files are upgraded in place, a newer one is refused (exit 65).
  • Verbs: fill, search, stats, forget, exclude, unexclude, help. help index lists nine topics (a page for each verb, and query, corpus and exit-status); each is a section 7 manual page, cmarkfind-TOPIC.7.md, written by make build. -json on every verb; exit codes follow the workspace convention and are documented under EXIT STATUS.
  • fill reads a site’s /.well-known/toc.opml from a folder or over the web. The web fill is polite: a pause per host, a named User-Agent, robots.txt, and conditional requests (ETag, If-None-Match) through markdownweb v0.0.5. A page the outline no longer lists is marked gone, not searched.
  • Curation: forget a site or everything, exclude and unexclude an address prefix.
  • Trickle: fill -batch N asks about at most N pages (never-asked first, then oldest checked) and says how many remain; -every and -until-done keep going.
  • the next cmarkbrowser release searches and fills the same file (S, F, -find).
