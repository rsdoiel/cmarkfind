NAME

cmarkfind-indexer — build, check and list a search index, and find a site’s published one

SYNOPSIS

cmarkfind indexer build [-chunk N] [SET]

cmarkfind indexer validate [SET]

cmarkfind indexer [list] [SET]

cmarkfind indexer discover SITE

cmarkfind indexer add [-reference] SITE

cmarkfind indexer refresh [SET]

DESCRIPTION

An index is a folder of compressed files, made from the pages of one set (cmarkfind-set(7)), that a program can search without the corpus (and, later, over HTTP). Each set has an index folder of its own and there is no index of the whole corpus. build writes the index of every set that needs one, or of SET: a set needs one when it has none, when the one there is not the one this corpus last built, or when what it is made from has changed (its pages after exclusions, its field mapping). A set that needs nothing is left alone, and build says how many it built and how many it left. Building again replaces an index: the generation number grows by one and files the new manifest no longer names are removed once they are ten minutes old, so a search that began before the rebuild can finish. The same pages always give the same files, so a set’s folder is a complete index that can be published as it is.

validate reads every file of an index and checks it against the digest in manifest.json. list says what an index holds: pages, chunks, generation and when it was built, and the words it holds without positions.

discover asks where a site publishes its index and says what it found, and changes nothing: no corpus is opened or made and no index file is fetched, only the manifest. SITE is a site address (https://example.org/) or the address of a manifest.json. For a site, discover reads /.well-known/cmarkfind.json at the site’s root, a small JSON object such as {“index”: “/cmarkfind/manifest.json”} whose “index” is a path or address on the same site, ending in manifest.json (at most 64 KiB; a key may not repeat; other keys are ignored). When that file is not there, discover tries /cmarkfind/manifest.json. A site that names a manifest that is missing is not searched at the default path instead. It prints the manifest’s address, how it was found, and the generation, page count and build time the manifest declares.

add makes a set from the index a site publishes, so that a site can be searched without reading its pages. By default the set is a mirror: the index’s files are fetched, checked against the digests in its manifest and kept in the set’s folder, and the set searches offline. With -reference it is a reference: only the manifest is kept (checked first), and every search fetches the files it reads, checking each one against the manifest, so it needs the site to be reachable and always reads the stored generation. Either way no page of the site is in the corpus: a hit shows the title and snippet the index holds, its tier is the set’s source (mirror or reference), and pins, tags and exclusions apply to it by address as to any hit. An exclusion drops the hit at search time and leaves the published index as it is. The set is named as a fill of the same site would name it, by the address of its outline (https://example.org/.well-known/toc.opml), or by the manifest’s address when add is given one, so a site cannot be both filled and mirrored: add of a name that is already a set exits 73, and fill of a mirror or reference exits 1. forget removes a mirror or reference with its folder, set ignore leaves it out of search, and set fields is refused (its field mapping is the publisher’s).

refresh reads the manifest of a mirror or reference again (of every one, without SET) and acts by its generation. A higher generation replaces what is held: a mirror fetches every file again, checks them and swaps them in whole, so the folder is always a complete index, and a reference stores the new manifest. An equal generation changes nothing and fetches no file. A lower generation is refused as a rollback, exit 65, and nothing changes. A set is as old as its last refresh: search never fetches a mirror and nothing refreshes by itself. list shows each mirror’s and reference’s manifest, the generation held and when it was last checked.

A mirror or reference that cannot be read when searching (the site is down, or a file fails its digest) is left out of search with a warning on standard error, and the others are searched. search-set of it fails with the cause. A search in which every set failed exits with the class of the first failure.

A word on a great many pages (a very common word such as “the”, in any language) can make its entry too big for one index file. Over about 2 MiB an entry is written without positions: the index still knows which pages hold the word and in which of title, description and body, and not where. A search for the word, a prefix, a field clause and AND, OR and NOT work as before. A phrase through such a word is checked against the text of each hit, so the answer is exact; a query for a phrase through one reads the pages it shows, and the pages above them that fail the check, and a limit keeps that small. The word is marked in a snippet from the page’s text. build prints these words with their page and position counts, list prints the words, and a fill, forget or exclude that rebuilds warns on standard error when the set of words has changed. A word of more than 128 bytes (a hash, a pasted blob) is not indexed at all. A build that still cannot fit a file names the word and exits 73; the index already in place is left as it was and keeps answering searches.

A word that is on more than a million pages is more than a reader will take (a posting list is one array, and a reader refuses one of over a million elements), so the build stops, names the word and its page count, and exits 73 instead of writing an index every search would call damaged; the index already in place is kept. A corpus of that size is far beyond what a rebuild after every fill suits.

A page whose own text is over one index file (about two million Chinese or Japanese characters in a page) cannot be written. The build leaves that page out, warns on standard error with its address, and goes on; the page stays in the corpus and is not searchable. stats lists such pages as “not indexed”.

The indexes are kept in the folder named by the CMARKFIND_INDEX variable, else a folder named index beside the corpus file (so -db moves both), one folder under it for each set. A fill, forget or exclude that changed pages builds the indexes of the sets it touched, and plain search reads them; a search that finds one missing, or built by something else, builds it first. forget removes the set’s index with its pages. An older cmarkfind kept one index for the whole corpus at the top of that folder; the first build removes it.

The folder is the corpus’s own: the first corpus to build into it writes a small file, .cmarkfind-owner, naming itself, and a second corpus pointed at the same folder is refused (exit 78) instead of rebuilding over the first on every search. A folder with no owner file goes to the first corpus that builds in it.

OPTIONS

-chunk N
Entries per word file when building. Default 10000.
-reference
With add: keep only the manifest and fetch the files at each search.
-json
Write the result as JSON.

EXIT STATUS

66 when SET is not a set or has no index (or there is no corpus), 2 when SET fits more than one set, 65 when an index is damaged, 73 when an index cannot be written. validate checks every set and exits with the first failure’s class. discover exits 1 when the site publishes no index (or its cmarkfind.json names a manifest that is missing), 2 for a missing or bad address, 65 when its cmarkfind.json or manifest is wrong (another origin, not a manifest.json, a repeated key, over 64 KiB, a format or analyzer this program does not know), and 69 when the site cannot be reached. add exits 2 for a missing or bad address, 66 when the site publishes no index, 65 when the index fails verification or needs a feature or analyzer this program lacks, 69 when the site cannot be reached, and 73 when the name is already a set; a failure leaves no set and no files behind. refresh tries every set and exits with the class of the first failure (65 for a rollback or a file that fails verification, 69 when a site cannot be reached), saying which set failed on standard error; a SET that is built here is exit 2, and one that does not exist is 66. See cmarkfind-exit-status(7).

EXAMPLES

cmarkfind indexer build
cmarkfind indexer build rsdoiel.github.io
cmarkfind indexer validate
cmarkfind indexer discover https://example.org/
cmarkfind indexer add https://example.org/
cmarkfind indexer add -reference https://example.org/
cmarkfind indexer refresh
