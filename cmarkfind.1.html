NAME

cmarkfind — a personal search engine for the Markdown web

SYNOPSIS

cmarkfind [-db FILE] VERB OPTIONS ARGS

cmarkfind -help | -version | -license

DESCRIPTION

cmarkfind keeps a corpus of Markdown pages in one SQLite file and searches it locally. It fills the corpus from a site’s table of contents (/.well-known/toc.opml), from a folder on disk or over the web, and searches with SQLite’s FTS5 query language. Nothing is sent anywhere by a search.

VERBS

fill OPTIONS SOURCE
Read the pages a site’s table of contents lists and store them. SOURCE is a folder (a site on disk, nothing fetched) or an http:// or https:// address (the site’s address, or its toc.opml). Pages already stored are asked for again only if they changed. A page the table of contents no longer lists is marked gone and is not searched. Options: -pause DURATION (between requests to one host, default 1s), -robots (obey robots.txt, default true), -user-agent TEXT, -max-pages N, -depth N (how many levels of included outlines), -json. A big site can be read a few pages at a time: -batch N asks about at most N pages (never asked ones first, then the ones checked longest ago) and says how many remain; run it again to continue. -every DURATION (with -batch) keeps going, a batch every DURATION, until interrupted, or with -until-done until nothing remains. A search says how many listed pages are not fetched yet.
search OPTIONS QUERY…
Search the corpus. QUERY is words, “phrases”, AND, OR, NOT and word*; text that is not valid query syntax is searched as plain words. Prints each hit’s title, address and tier, and the matching text; the count and how many pages were searched go to standard error. Options: -limit N (default 10), -json. Use – before a query that starts with a dash.
stats OPTIONS
Say what the corpus holds: pages, pages gone, counts by site and tier, the file’s size and schema version. Option: -json.

forget OPTIONS SITE forget -all : Delete the pages stored from one site (named as for fill), or every page. Exclusions are kept. -dry-run says how many pages would go and deletes nothing. Exit 1 when SITE stored nothing.

exclude OPTIONS PREFIX exclude -list : Keep every page whose address starts with PREFIX out of the corpus: stored pages under it are deleted and later fills skip (and do not request) them. PREFIX is an http:// or https:// address, matched as plain text; end a folder with a slash. -list shows the rules.

unexclude PREFIX
Remove an exclusion. Pages come back with the next fill. Exit 1 if there was no such rule.
help [TOPIC]
Show this page, or one topic’s page. help index lists the topics: one for each verb, and query, corpus and exit-status. Each is also a manual page of section 7, cmarkfind-TOPIC(7).

OPTIONS

-db FILE
The corpus file. Default: the CMARKFIND_DB variable, else cmarkfind/corpus.db in the user’s data directory. fill creates it; search and stats need it.
-help, -version, -license
Show the help, the version or the license.
-json
On every verb, write the result as JSON on standard output. A failure is then also written there as {“error”: “…”, “class”: “…”, “code”: N}.

EXIT STATUS

0
Success.
1
search found nothing; forget’s SITE or unexclude’s PREFIX had nothing to act on; robots.txt forbids the table of contents.
2
Bad command line: unknown verb or option, missing argument, bad value.
65
The file is not a corpus or has a newer schema; a source is malformed.
66
A folder, the corpus (for search and stats) or a table of contents is missing.
69
The site cannot be reached. A fill in which some pages failed finishes, prints its counts and exits with the class of the first failure.
73
The corpus file or its directory cannot be created.
75
The corpus is locked by another program; try again.
77
The system refused access.
70
A bug.

EXAMPLES

cmarkfind fill ~/Sites/example.org
cmarkfind fill https://rsdoiel.github.io
cmarkfind search oberon compiler
cmarkfind search -json '"shallow water"' | jq .
cmarkfind stats
cmarkfind exclude https://example.org/drafts/
cmarkfind forget ~/Sites/example.org
